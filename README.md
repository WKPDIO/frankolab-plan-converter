# FrankoLab · конвертер плану лікування

Перетворює план лікування з ClinicCards (PDF) на зрозумілий пацієнту PDF у стилі FrankoLab:
етапи й блоки, просте пояснення кожної послуги з картинкою, зубна формула кожного етапу,
пам'ятки перед і після процедур, кошторис у гривнях і євро. Кожна сума звіряється з оригіналом —
якщо хоч одна не збігається, конвертер зупиняється і нічого не видає.

## Як це працює

```
PDF з ClinicCards ─► parse_clinicards.py ─► render.py (довідник послуг) ─► templates/plan.html.j2 ─► PDF
                     читає етапи, блоки,     описи, картинки, «У ціні»,     верстка, шрифти,
                     зуби, ціни, знижки      кольори, пам'ятки, формула     кольори бренду
```

Коли з'явиться API ClinicCards, міняється лише перший крок — усе інше лишається.

Якщо в плані ClinicCards є позначки виконання (✓ — виконано, ● — ні), конвертер показує їх у PDF: «виконано» біля
послуги й блоку, а під загальною сумою — «Уже виконано» і «Залишилось виконати». Ці суми теж звіряються з рядками
«Виконано» / «Невиконані» в оригіналі.

## Файли — і що де міняти

| Файл | Що в ньому | Хто може міняти |
|---|---|---|
| `data/services.json` | довідник послуг: опис (`desc`), картинка (`pic`), що входить у ціну (`incl`), мітка «наша лабораторія» (`lab`), що малювати на зубі (`effect`); категорії блоків з кольорами фону; загальна примітка (`included_everywhere`) | адміністратор / лікар — це текст |
| `data/memos.json` | пам'ятки пацієнту: коли показувати (`trigger`), де (`before`/`after`), пункти | адміністратор / лікар |
| `templates/plan.html.j2` | верстка сторінок, шрифти, кольори, порядок розділів, таблиця | розробник |
| `illustrations.py` | 45 ілюстрацій процедур (SVG) | розробник |
| `stagechart.py` | зубна формула етапу: як кожна процедура малюється на зубі, легенда | розробник |
| `graphics.py` | анатомічні форми зубів, загальна зубна формула, іконки блоків | розробник |
| `parse_clinicards.py` | читання PDF з ClinicCards | розробник |
| `review_plans.py` | перевірка пачки планів: що скаже конвертер, послуги без опису, назви блоків, ціни проти прайсу | розробник |
| `examples/` | 8 знеособлених планів для перевірки після змін (`plan_7`–`plan_9` — з позначками «виконано»; `plan_8` — All-on-6 на обидві щелепи з тимчасовим протезом All-on-4; `plan_9` — пародонтологія, квадранти, апостроф у прізвищі) | — |

## Запуск

```bash
pip install -r requirements.txt
python3 -m playwright install chromium

# один план (PDF з ClinicCards або розібраний JSON), за бажанням — панорама
python3 render.py plan.pdf out/ panorama.png

# перевірка після будь-яких змін: перезбирає 8 прикладів (PDF і кабінет) і звіряє суми
python3 check_examples.py

# пачка нових планів: звіт про кожен (і ціни проти прайсу) → out/review/report.md, out/review/maps.html
python3 review_plans.py out/review плани/*.pdf --prices Price.xlsx

# аркуш з усіма ілюстраціями → out/illus.png
python3 preview_illustrations.py 8
```

Для сайту чи іншої програми є функція `render.render_plan(src, out_dir, pano=None, preview=None)` —
повертає шлях до PDF і звіт (кількість позицій, суми, послуги без опису).

## Кабінет пацієнта (прототип)

`portal/cabinet.py` будує сторінку кабінету для телефона з того самого плану: етапи зі статусами
(завершено / зараз / попереду), процедури, що розгортаються з описом, картинкою й «У ціні», пам'ятки,
зубна формула кожного етапу, оплати (сплачено, до сплати за виконане, залишок за планом) і виконані роботи.

```bash
python3 portal/cabinet.py examples/plan_2.json out/cabinet.html --demo
```

Прогрес і оплати приходять окремо від плану — у форматі, який заповнить API ClinicCards
(виконані роботи: послуга + зуб + дата; оплати: дата + сума + валюта). Поки API не підключено,
`--demo` підставляє приклад. Для плану, завантаженого офісом, прогрес береться з позначок «виконано» в PDF,
а замість оплат кабінет показує «виконано на суму / залишилось» — борг без даних про оплати не рахуємо.

## Сайт: конвертер для офісу + кабінет пацієнта

Один застосунок (`web/`), дві частини:

| Адреса | Хто | Що |
|---|---|---|
| `/login`, `/` | офіс, один спільний пароль | закинути PDF з ClinicCards (+ панораму) → готовий план: завантажити PDF, відкрити, подивитися «як побачить пацієнт» |
| `/r/<код>` | офіс | сторінка готового плану; файли пацієнта видаляються через `TTL_MINUTES` (60 хв) або кнопкою «Видалити зараз» |
| `/cabinet` | пацієнт | вхід за номером телефону — запрацює після підключення ClinicCards і SMS |
| `/cabinet/demo` | усі | демо-кабінет на знеособленому прикладі |

Нічого про пацієнтів не зберігається: оригінальний PDF видаляється одразу після розбору, решта — після TTL.
Якщо хоч одна сума не збігається з ClinicCards, план не створюється.

```bash
pip install -r requirements.txt -r web/requirements.txt
python3 -m playwright install chromium
OFFICE_PASSWORD=пароль SECRET_KEY=будь-який-довгий-рядок COOKIE_SECURE=0 uvicorn web.app:app --reload
```

### Розгортання (Render)

1. render.com → увійти через GitHub.
2. **New → Blueprint** → вибрати цей репозиторій. Render прочитає `render.yaml` (Docker, Франкфурт, безкоштовний план).
3. Ввести `OFFICE_PASSWORD` — пароль офісу. `SECRET_KEY` Render згенерує сам.
4. Після збірки (5–10 хв) сайт доступний за адресою `https://frankolab-plans.onrender.com` (або схожою).
   Кожен push у `main` оновлює сайт автоматично.
5. Власна адреса (необов'язково): Render → Settings → Custom Domain, потім запис CNAME у DNS домену.

Безкоштовний план засинає після 15 хв без відвідувань і прокидається приблизно за хвилину; процесор у ньому слабкий, тож PDF створюється довше.
Якщо це заважає або не вистачає пам'яті для Chromium — перейти на Starter (Render → Settings → Instance Type).

### Підключення ClinicCards

Усе, що бачить пацієнт, читається через «джерела» (`web/sources.py`): `PdfSource` (PDF з офісу), `DemoSource` (демо),
`ClinicCardsSource` (API). Щоб увімкнути живий кабінет:

1. Власник клініки створює API-ключ (ClinicCards → Налаштування → Інше → Налаштування клініки → API)
   і додає його в Render → Environment як `CLINICCARDS_API_KEY`.
2. У `web/clinicards_api.py` заповнити шляхи методів (`find_patient_by_phone`, `performed_works`, `payments`,
   за наявності — `treatment_plans`) за документацією API. Формати, які вони мають повертати, описані в коді.
3. Підключити SMS-провайдера для коду входу (`/cabinet`).

Якщо API не віддає плани лікування, план береться з PDF, завантаженого офісом один раз на пацієнта,
а виконані роботи й оплати — з API.

## Правила

- **Дані пацієнтів у репозиторій не кладемо**: ні PDF, ні панорами, ні розібрані плани з іменами.
  Для тестів — лише знеособлені приклади в `examples/`.
- **Після кожної зміни** — `python3 check_examples.py` і погляд на PDF у `out/examples/`.
- Тон описів — за брендбуком: просто, спокійно, без обіцянок («гарантовано», «100 %», «безболісно»),
  без тиску. Конвертер сам попереджає, якщо такі слова з'являться в описах.
- Нова послуга без опису не ламає план: вона виходить без пояснення, а конвертер повідомляє, що опис треба дописати.

## Відкриті питання

- «Коронка/накладка склокерамічна» на зубній формулі малюється як коронка (`effect: crown`).
